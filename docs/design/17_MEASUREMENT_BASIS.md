# 17. Measurement Basis

v0.2의 모든 수치는 실제 데이터 측정값이다. 이 문서는 그 출처와 조건, 그리고 한계를 기록한다.

**수치를 인용할 때는 이 문서의 조건을 함께 인용해야 한다.** 조건 없는 수치는 검증 불가능한 목표가 된다.

## 측정 환경

| | |
|---|---|
| CPU | Intel Xeon @ 2.10GHz, **2 코어** |
| 검색 구현 | Rust, `opt-level=3`, `lto=true`, `codegen-units=1` |
| 파서 | tree-sitter 0.26 (python / go / typescript / rust) |
| 대조군 | CPython 3.11 `ast` |
| 통계 | 워밍업 후 15~60회 반복, p50 / p95 / p99 |

> **2코어는 실사용 개발 머신(8~16코어)보다 훨씬 약하다.** 절대값이 아니라 한계점의 위치와 상대 기여도로 읽어야 한다. 병렬 효율 0.86이 실측되었으므로 코어 수에 따른 외삽이 가능하다.

### 문서→코드 참조 해석률 (R6, Sphinx role)

측정일 2026-08-17. django(`docs/**/*.txt` 675개)를 `--depth 1` 로 클론해 정규식으로 Sphinx role(`:class:` `:func:` `:meth:` `:attr:` `:mod:` `:exc:` `:data:` `:obj:`)을 추출하고, 저장소 `.py` 를 `ast` 로 파싱해 만든 모듈별 접근 가능 이름(정의 + import 재수출) 목록과 대조해 해석했다.

```text
총 코드 참조            10,203      (:class: :func: :meth: :attr: :mod: :exc: :data: :obj:)
  표준/외부 라이브러리       582  (5.7%)   datetime · unittest · pathlib
  저장소 안을 가리킴       9,621  (94.3%)
  경로까지 확인 해석       7,867  (81.8%)  ← 실제 링크가 되는 건수
  이름만 일치            1,285
  미해석                  469  (4.9%)
```

**7,867은 하한이다.** 미해석 469건은 문서 문제가 아니라 측정 도구 한계다 — 상속을 따라가지 않아 `User.is_staff` 처럼 부모 클래스에 정의된 속성을 못 찾는다.

**짧은 이름 참조가 2,979건(전체의 31%)이다.** `:class:`QuerySet`` 처럼 경로 없이 쓴 것. Sphinx는 `currentmodule` 문맥으로 이를 해석하는데, 이 제품은 그 문맥을 재현하거나 이름 유일성으로 대체 판정해야 한다. **R1(이름 대조)과 동일한 모호성 문제다.** R6 구현 비용으로 산입할 것 — 정확한 링크만 남긴다면 위 7,867건도 짧은 이름 몫만큼 줄어든다.

### 생태계별 문서→코드 참조 밀도

측정일 2026-08-17. 각 저장소를 `--depth 1` 로 클론해 문서 파일당 코드 심볼 참조 문법(Sphinx role / mkdocstrings `:::` / Doxygen 태그)의 건수를 센 것. "밀도" = 참조 수 ÷ 문서 파일 수.

| 저장소 | 생태계 | 문서 | 참조 | 밀도 |
|---|---|---:|---:|---:|
| scikit-learn | Python/Sphinx | 190 | 7,301 | 38.4 |
| django | Python/Sphinx | 675 | 10,203 | 15.1 |
| flask | Python/Sphinx | 76 | 563 | 7.4 |
| requests | Python/Sphinx | 16 | 83 | 5.2 |
| fastapi | Python/MkDocs | 155 | 61 | 0.39 |
| fmt | C++ | 4 | 4 | ~1.0 |
| rapidjson | C++/Doxygen | 12 | 1 | 0.08 |
| tokio / vue core / hugo | Rust / TS / Go | — | 0 | 0 |

fastapi는 `mkdocstrings` `:::` 문법을 쓴다. fastapi는 14개 언어본이 있어 영어본(`docs/en/docs`)만 세어 정규화했다.

**핵심 구분 — 참조가 어디에 있는가.** django 등 Sphinx 프로젝트는 **별도 문서 파일**이 코드 심볼을 가리킨다 — 이것이 R6가 노리는 대상이다. 반면 tokio(~727건) / vue(~121건) / hugo(~29건)의 참조는 전부 **코드 주석 안**의 것(rustdoc intra-doc link, TSDoc `{@link}`)이다. 코드→코드이며 IDE가 이미 제공하는 기능이므로 R6의 대상이 아니다.

**마크다운 링크는 무의미했다.** django·hugo·vue·tokio 4개를 통틀어 코드 파일을 가리키는 마크다운 링크는 **2건**. 개인 프로젝트 폴더(문서 175개, 별도 표본)에서도 **1건**. `06_POLYGLOT_PARSERS.md` 의 문서 추출 대상 "링크"만으로는 R6가 잡는 관계를 잡지 못한다.

**확신이 낮은 항목:**

- Doxygen(C++) 표본은 rapidjson 하나(문서 12개)뿐이다. **"C++ 생태계는 Doxygen 참조를 안 쓴다"고 단정할 수 없다.** 대형 C++ 프로젝트는 미측정이다.
- fmt 표본은 문서 4개로 통계적 의미가 거의 없다.

### 유사도 파라미터

45개 조합 스윕 결과 정밀도가 파라미터에 거의 무관(91.6~93.6%)했다. 유사도 분포가 이봉형이기 때문이다.

| 설정 | 복구 | 정밀도 | 인덱스 항목 |
|---|---:|---:|---:|
| k=4, sketch=96, thr=0.60 | 809 | 92.3% | 1,518,274 |
| **k=3, sketch=32, thr=0.40** | **1,515** | **92.9%** | **946,094** |

정밀도 측정법: S3(qualname 전역 유일)로 해결된 심볼은 정답을 알 수 있다. 그 집합에 S4 매처를 돌려 같은 대상을 고르는 비율을 쟀다.

## 측정의 한계

수치를 신뢰할 수 있는 범위를 명확히 하기 위해 기록한다.

1. **2코어 Xeon 2.1GHz.** 실사용 머신보다 약하다. 병렬 효율 0.86으로 외삽 가능하나 절대값은 보수적으로 읽어야 한다.
2. **검색 코퍼스가 극단 케이스다.** 232K는 대형 저장소 5개를 합친 규모다. 실제 vault 하나는 1K~50K가 일반적이며 그 구간은 전부 여유 있게 통과한다.
3. **제안 엔진의 정밀도를 측정하지 못했다.** 자동 지표 두 개가 실패했고 세 번째도 실존 심볼을 버린다. **정밀도 수치를 제시하지 않는 것이 정직한 상태다.** 승인율도 마찬가지로 미측정이다.
4. **call edge의 UNIQUE 판정은 이름 단위다.** import 정보를 결합하면 `bare` 유일률은 73.0%보다 올라간다. 이 값은 **하한**이다.
5. **인덱스 크기의 TF/위치 포함 수치는 추정이다.** doc ID만 저장한 5.5%는 실측이지만 7.3% / 21.8%는 계산값이다.
6. **TypeScript 표본이 작다.** 2 저장소 2,314 심볼. date-fns는 과거에 `.js` 였고 prettier는 `.mjs` 비중이 커서 `.ts` 심볼이 적었다. 다른 언어보다 신뢰도가 낮다.
7. **모든 측정에서 vendored 코드를 제외했다.** 실제 사용자 vault도 그럴 것이므로 타당하지만 `.gitignore` 기반 자동 제외가 전제된다.
8. **GONE(심볼 소멸) 판정이 유사도 오라클에 의존한다.** 완전히 재작성되었지만 개념적으로 같은 함수는 GONE으로 분류되어 분모에서 빠진다. 복구율을 과대평가하는 방향이다.
9. **Python / Go / TypeScript / Rust만 측정했다.** Java, C++, JS는 미측정이다.
10. **모든 측정이 "어떻게 만들 것인가"에 대한 것이다.** "만들 가치가 있는가"는 측정하지 않았고 측정할 수 없다. 제품 리스크는 그대로 남아 있다.
11. **R6(Sphinx role)는 django 하나로만 정밀 측정했다.** 생태계별 밀도(B)는 8개 저장소를 비교했지만, 해석률(7,867/81.8%) 세부 분석은 django 675개 문서만 대상이다.
12. **R6의 짧은 이름 참조(31%, 2,979건) 처리 방식은 미확정이다.** `currentmodule` 문맥 재현이냐 이름 유일성 대체 판정이냐에 따라 최종 해석률이 달라진다.
13. **R6의 승인율·정밀도는 미측정이다.** R1과 마찬가지로 실사용 로그가 있어야 알 수 있다.

## 재현

측정 코드 일체는 별도 패키지 `vault-bench` 로 보관한다.

```text
search/    Rust — 퍼지 검색 벤치마크 3종
resolve/   Python — 파일 링크 복구율 2종
symbol/    Python — 심볼 복구율 2종, 파서 복원력 1종
m1_m6/     Python + Rust — 언어별 복구율, 제안 엔진, call edge,
                            정합성 스캔, 파라미터 스윕, 인덱스 규모
raw_output/ 원본 stdout + 통합 데이터셋 (measurements.json)
```

코퍼스는 공개 저장소이므로 누구든 재현할 수 있다. 다만 HEAD가 움직이므로 수치는 정확히 재현되지 않는다. 재현 시에는 측정일(2026-08-16) 기준 커밋으로 고정하는 것을 권한다.

R6(Sphinx role, 위 "문서→코드 참조 해석률" / "생태계별 문서→코드 참조 밀도") 은 별도 측정이다. 측정일 2026-08-17. `--depth 1` 로 클론한 공개 저장소를 정규식(Sphinx role 추출)과 `ast`(모듈별 접근 가능 이름 목록) 스크립트로 대조했다. `vault-bench` 패키지와 별도이며 재현 시 2026-08-17 기준 커밋으로 고정할 것을 권한다.
