# 02. Core Principles

## 1. Local-first

핵심 데이터와 인덱스는 사용자 PC에 저장한다. 기본 기능은 인터넷 연결 없이 작동해야 한다.

## 2. Original-file-first

원본 파일을 전용 포맷으로 강제 변환하지 않는다.

```text
README.md
router.py
config.json
experiment.ipynb
```

는 그대로 유지한다. 앱을 삭제해도 원본 파일은 그대로 남는다.

## 3. Source-of-truth 분리

시스템 데이터를 성격에 따라 분리한다. **재생성할 수 없는 것과 재생성할 수 있는 것을 섞지 않는다.**

```text
.vault/      재생성 불가. git 커밋 대상. 사람이 읽을 수 있음
             manual link, alias, 승인 이력, 설정

.vault-ai/   순수 파생물. 언제든 삭제 가능
             인덱스, 파서 캐시, 유사도 스케치, 미승인 제안
```

v0.1은 둘을 한 곳에 두면서 "삭제해도 복구 가능"이라고 규정해 자체 모순이었다.

## 4. Algorithm-first

핵심 구조화에 AI를 사용하지 않는다.

```text
코드     → Tree-sitter
JSON     → JSON parser
문서     → Markdown / reStructuredText parser
CSV      → table parser
Jupyter  → notebook parser
관계 제안 → 결정론적 규칙
```

동일 입력에는 동일 결과가 나오도록 설계한다.

**단, 부분 결과를 허용한다.** 편집 중 문법 오류가 있는 파일에서 파싱이 완전히 실패하는 것보다 살아남은 심볼을 반환하는 것이 낫다. "재현 가능"과 "전부 아니면 전무"는 다르다.

## 5. Human-link-first

중요한 의미 관계는 사용자가 주도한다.

자동 생성이 허용되는 것은 프로그램이 결정론적으로 확정할 수 있는 관계다.

```text
defines / imports / contains / parent_of / json_pointer
```

**그리고 그 관계에는 신뢰도를 붙인다.** 확실한 것(`defined_in`)과 불확실한 것(`calls`)을 같은 라벨로 저장하면 신뢰 수준 판단이 무의미해진다.

AI의 의미 추론은 Vault Graph를 자동 수정하지 않는다.

## 6. Suggest, don't decide

Human-link-first를 그대로 두면 vault를 처음 열었을 때 Semantic Web이 텅 빈다. 링크를 걸어야 가치가 생기는데, 가치가 안 보이니 링크를 걸지 않는다.

따라서 시스템은 **후보를 만들되 결정하지 않는다.**

```text
결정론적 규칙 → 후보 생성 → 사용자 1클릭 승인 → 링크 확정
```

이는 Human-link-first를 위반하지 않는다. 결정권이 여전히 사용자에게 있기 때문이다.

**그리고 후보를 필터링하지 않고 랭킹한다.** 자동 정밀도 판정을 시도했다가 정답을 버리는 실패를 두 번 겪었다. 시스템이 확신할 수 없는 것을 확신하는 척하지 않는다.

## 7. Polyglot

Markdown을 특수한 중심 포맷으로 두지 않는다. 각 파일 형식은 해당 구조를 최대한 보존하며 공통 IR에 연결된다.

문서 형식도 `.md` 하나가 아니다. `.rst`, `.txt` 를 같은 지위로 다룬다.

## 8. Search-first

파일 검색 성능은 부가기능이 아니라 핵심 KPI다.

**목표는 하드웨어 조건과 함께 수치로 명시한다.** "빨라야 한다"는 KPI가 아니다.

## 9. AI-optional

AI가 없어도 프로그램 핵심 기능이 완전해야 한다. 콜드스타트 해소까지 포함해서다.

## 10. MCP-first AI Integration

외부 AI는 MCP를 통해 Vault의 검색·읽기·Graph 기능을 사용한다.

## 11. Progressive Disclosure

내부 기능이 복잡하더라도 기본 UI는 단순해야 한다.

초기 사용자에게는 파일 / 검색 / 에디터 / 관련 항목 정도만 보이고, Graph와 고급 기능은 필요할 때 연다.

## 12. Incremental by Default

파일 하나가 바뀌었다고 전체 Vault를 다시 처리하지 않는다. 변경된 파일과 관련 인덱스만 갱신한다.

## 13. Trust but verify

OS 이벤트는 유실된다. Watcher를 신뢰하되 정합성은 별도로 보장한다.

```text
watcher 이벤트     저지연 힌트
주기 정합성 스캔    정확성 보장
```

"인덱스가 가끔 틀린 검색기"는 검색기로서 실패다.

## 14. Addresses resolve, not point

주소를 저장 시점에 물리적 위치로 고정하지 않는다. 논리 주소를 저장하고 조회 시점에 계단식으로 해석한다.

이 때문에 파일이 움직여도 링크가 살아남는다. 그리고 복구에 실패해도 **링크를 삭제하지 않는다** — 사용자가 고칠 수 있는 정보를 시스템이 버려서는 안 된다.

## 15. Measure before deciding

이 문서의 여러 원칙은 v0.1에서 직관으로 세워졌고, 그중 일부는 측정 결과 틀렸다.

```text
"10만 경로 선형 스캔은 수 ms"          → 18.8ms. 스코프를 바꿔야 했다
"이름 매칭 단계는 기여도가 낮다"        → 파일은 맞고 심볼은 틀렸다 (13.7%p)
"AST는 과거 문법에서 실패한다"          → 0.2%. 진짜 원인은 편집 중 상태였다
"지역성으로 제안 정밀도를 판정할 수 있다" → 정답이 교차 관계라 실패했다
```

되돌리기 비싼 결정(파서 백엔드, 저장소 구조, 주소 체계)은 **구현 전에 측정한다.** 측정 근거는 `17_MEASUREMENT_BASIS.md` 에 조건과 한계를 함께 기록한다.

그리고 **측정하지 못한 것을 측정한 척하지 않는다.** 제안 엔진의 정밀도와 승인율은 아직 모르며, 문서에도 수치를 쓰지 않는다.
