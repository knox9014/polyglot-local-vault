# 12. Engineering Decisions

v0.1에서 이 문서의 이름은 "12 Engineering Decisions **TODO**" 였고, 9개 항목이 "구현 단계에서 벤치마크 후 선택"으로 남아 있었다.

**벤치마크를 수행했다.** 9개 중 6개가 실측으로 확정되었고, 확정 항목은 `14_LOCKED_DECISIONS.md` 로 이동했다. 이 문서에는 **아직 결정되지 않은 것만** 남긴다.

측정 조건과 수치의 출처는 `17_MEASUREMENT_BASIS.md` 참조.

## 확정된 항목 (요약)

| 항목 | 결정 | 근거 |
|---|---|---|
| Parser infrastructure | Tree-sitter 단일 | 편집 중 심볼 보존 96.9% vs ast 16.7% |
| Search index 구조 | 3층 (in-memory path / 역인덱스 / 관계 저장소) | 퍼지 매칭은 역인덱스로 표현 불가 |

| 유사도 파라미터 | k=3, sketch=32, thr=0.40 | 45조합 스윕, 복구 +87% |

| call edge 범위 | bare/self만 생성, attr 제외 | 유일률 73.0/75.3% vs 30.3% |

**결정 시점**: Phase 1 시작 전. Phase 1이 최소 UI를 포함하므로 더 미룰 수 없다.

## 미결 ② Search Ranking 가중치

초기 후보 순서:

```text
filename exact
> filename prefix
> symbol exact
> path match
> content exact
> BM25
> graph relation
```

퍼지 매칭 내부 가중치(경계 / camelCase / 연속 매치 / 파일명 영역 보너스)의 상대값도 미정이다. 현재 구현에서는 각각 8 / 7 / 8 / 4를 썼으나 근거는 없다.

**이것은 벤치마크로 정할 수 없다.** 정답이 사용자의 의도에 달려 있기 때문이다. 실사용 로그(무엇을 입력하고 몇 번째 결과를 선택했는가)로 조정해야 한다.

**결정 시점**: Phase 1 이후 실사용 데이터 축적 후.

## 미결 ③ MCP Tool Schema 세부

4툴 압축은 결정했으나 다음은 미정이다.

- `search` 의 `filters` 스키마
- `read` 의 `outline` 모드가 반환하는 구조의 상세
- `neighbors` 의 `rel` 어휘 표준화
- 응답 크기 상한 및 페이지네이션
- 에러 형식

**이것도 벤치마크로 정할 수 없다.** 실제 모델 하네스로 호출 효율을 재야 한다.

**결정 시점**: Phase 4. 측정 항목은 `08_MCP_AND_AI.md` 에 정의되어 있다.

## 미결 ④ 관계 저장소 구현

3층 구조에서 "임베디드 관계 저장소"의 구체 선택이 남았다.

후보:

- SQLite (재귀 CTE로 순회)
- 자체 인접 리스트 + mmap
- 임베디드 그래프 라이브러리

**대형 Graph DB를 도입하지 않는다**는 것은 확정이다. 규모가 이를 요구하지 않는다 — 측정상 manual link는 수백~수천 개 규모이고, 파서 엣지는 재생성 가능한 캐시다.

**결정 시점**: Phase 3 시작 전. 1-hop 조회가 지배적이므로 요구사항이 가볍다.

## 미결 ⑤ 플랫폼별 세부

측정하지 않았고 구현 중 부딪힐 항목들이다.

| 항목 | 내용 |
|---|---|
| Windows 경로 | 대소문자 무시 파일시스템, 260자 제한, `\` vs `/` 정규화 |
| 인코딩 | UTF-8 아닌 파일(CP949 등), BOM, 잘못된 바이트 |
| 심볼릭 링크 | 순환 링크, vault 밖을 가리키는 링크 |
| 인덱스 스키마 버전 | 앱 업데이트 시 마이그레이션 vs 전체 재인덱싱 |
| 다중 인스턴스 | 같은 vault를 두 창에서 열 때의 락 |
| 대용량 파일 임계 | 현재 본문 1MB / 파싱 5MB. 실사용으로 조정 |

**결정 시점**: 해당 Phase에서 순차 처리.

## 벤치마크 회귀 테스트

확정된 항목은 되돌아가지 않도록 CI에 건다.

```text
고정 코퍼스 (1K / 10K / 50K / 100K 파일)
  keystroke p95 < 16ms (파일명 스코프)
  cold 인덱싱 < 30s @ 100K
  인덱스 크기 / 원본 < 10%
  정합성 스캔 < 500ms @ 100K

고정 저장소 히스토리
  파일 링크 복구율 > 95%
  심볼 링크 복구율 > 93%

문법 오류 주입
  심볼 보존율 > 95%
```

측정 코드는 `vault-bench` 패키지에 있다. (→ `17_MEASUREMENT_BASIS.md`)
