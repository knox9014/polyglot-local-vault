# 11. Security, Privacy, Reliability

## Local-first 보안

핵심 데이터는 로컬에 저장한다. 기본 동작에 네트워크가 필요 없다. 영어 사전 등 제안 엔진이 쓰는 정적 데이터도 앱에 동봉한다.

## 원본 파일 보호

앱 내부 데이터와 원본을 분리한다.

```text
project files
+
.vault/       source of truth (링크, alias, 승인 이력, 설정)
.vault-ai/    파생물 (인덱스, 캐시, 스케치, 미승인 제안)
```

인덱싱이나 Graph 처리 때문에 원본을 수정하지 않는다.

## 손상 대응

`.vault-ai/` 가 삭제되거나 손상되어도 원본 파일과 git을 다시 스캔해 인덱스와 파생 Graph를 재구축할 수 있다.

**v0.1의 문제**: 같은 문서가 "`.vault-ai/` 는 원본보다 우위의 source of truth가 되어서는 안 된다"고 규정했으나, manual link도 그 안에 있었다. manual link는 재스캔으로 복구할 수 없는 유일한 데이터다.

**v0.2의 해결**: manual link를 `.vault/` 로 옮겼다. 이제 규정이 실제로 성립한다.

```text
.vault-ai/ 삭제  → 재인덱싱으로 100% 복구
.vault/ 삭제     → manual link 유실. 단 git 커밋 대상이므로 git에서 복원 가능
```

`.vault/links.jsonl` 이 append-only이므로 부분 손상 시에도 손상 지점까지는 읽을 수 있다.

## Secret 처리

개발 프로젝트에는 다음이 존재할 수 있다.

```text
.env / API keys / credentials / private certificates / *.pem / *.key
```

대응:

- ignore 규칙 (`.gitignore` 문법 재사용 + secret 기본 패턴)
- ignored 파일은 인덱싱하지 않고 MCP로 노출하지 않음
- 읽기 권한 제어

**ignore 규칙은 Phase 0 필수 항목이다.** 보안 이유뿐 아니라 제안 엔진의 정밀도 문제이기도 하다. (→ `16_SUGGESTION_ENGINE.md`)

## MCP 보안

외부 AI가 모든 파일에 자동 접근하지 않도록:

- read-only 기본, write 툴 분리
- link write는 명시적 승인 후에만, 불변 `suggestion_id` 기준
- ignored 파일 비공개
- `mode="outline"` 으로 본문 없이 구조만 반환 가능 (최소 권한)
- 감사 로그 — 어떤 툴이 무엇을 읽었는지 기록

## Parser 신뢰성

AI 추론 대신 결정론적 Parser를 쓰는 핵심 이유는 재현성이다. 같은 파일은 같은 구조로 분석되어야 한다.

**단, "재현 가능"과 "전부 아니면 전무"는 다르다.**

편집 중인 파일은 문법 오류 상태를 반드시 지나간다. 측정 결과 CPython `ast` 는 이 상황에서 심볼을 평균 16.7%만 보존했고, 파일 끝에서 함수를 타이핑하는 중에는 **0.0%** 였다. Tree-sitter는 각각 96.9%와 99.9%였다.

따라서:

```text
문법 오류 시 부분 파싱 결과를 반환한다 (partial flag를 붙여서)
인덱서는 부분 결과를 반영하되 기존 심볼을 통째로 지우지 않는다
같은 입력에는 같은 부분 결과가 나온다 (재현성은 유지)
```

## Graph 신뢰성

관계의 출처와 신뢰도를 함께 저장한다.

```text
origin      manual / parser / git / suggested / imported
confidence  certain / probable / heuristic
```

v0.1은 `origin` 만 두어 `defined_in`(100% 확실)과 `calls`(측정상 유일 해석률 48.5%)를 같은 취급했다. 사용자와 시스템이 신뢰 수준을 판단할 수 없었다.

기본 UI는 `certain` 만 표시한다. `probable` 이하를 기본으로 켜면 오탐이 화면을 채우고, 한 번 신뢰를 잃은 패널은 회복이 어렵다.

## 링크 무결성

- 링크는 논리 주소로 저장되며 조회 시점에 해석된다.
- **복구에 실패해도 링크를 삭제하지 않는다.** BROKEN으로 표시하고 마지막 알려진 주소를 함께 보여준다.
- 사용자가 고칠 수 있는 정보를 시스템이 임의로 버리지 않는다.

## 동시성

- 같은 vault를 두 인스턴스가 열면 인덱스 동시 쓰기로 손상될 수 있다. 락 파일로 방지한다.
- `.vault/*.jsonl` 은 append-only이므로 읽기는 락 없이 안전하다.

## 인덱스 버전

앱 업데이트로 인덱스 포맷이 바뀔 수 있다. `.vault-ai/state/` 에 스키마 버전을 기록하고, 불일치 시 전체 재인덱싱한다.

재인덱싱 비용은 측정되었다 — 100K 파일 18.5초. 사용자에게 진행률을 보여주면 감당 가능한 수준이다. 마이그레이션 로직을 만드는 것보다 재인덱싱이 안전하다.

## 무엇을 보장하지 않는가

정직하게 기록한다.

- **암호화를 제공하지 않는다.** 로컬 파일시스템 권한에 의존한다.
- **제안 엔진의 정밀도를 보장하지 않는다.** 측정하지 못했다. 그래서 후보를 자동 승인하지 않고 사용자 판정을 요구한다.
- **`calls` 관계의 정확성을 보장하지 않는다.** 그래서 `probable` 로 표시하고 기본 UI에서 숨긴다.
- **링크 복구를 100% 보장하지 않는다.** 파일 95.7%, 심볼 93.7%이며 나머지는 BROKEN으로 표시된다.
