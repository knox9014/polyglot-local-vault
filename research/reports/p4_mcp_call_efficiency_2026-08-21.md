## 이 수치를 신뢰하면 안 되는 이유 — 편향

**측정자와 측정 대상이 같다.** 이 툴을 직접 구현한 모델이 같은 세션에서 스스로를
측정했다. 스키마·인자·응답 형태를 완전히 알고 있으므로 "잘못된 툴 선택 0%"는
**처음 보는 모델에게 재현될 것이라고 볼 근거가 없다.** 완화 불가능하며, 이 항목이
`08` 이 "모델 하네스 없이는 측정 불가"라고 적어둔 바로 그 이유다.

표본 추출만은 편향을 뺐다 — 고정 시드로 실제 데이터에서 뽑아, 쉬운 질의를 고를 여지를
없앴다. 그 결과 실제로 표본에 인덱스 밖 파일 2건이 섞여 들어왔고(아래), 그것까지 포함해
집계했다.

**남은 한계**

```text
1회 호출이 "답이 맞다"를 뜻하지 않는다   링크 데이터 자체가 맞는지는 별도 문제다

```

## 측정 중 드러난 것 — 버그 3건

측정을 **준비하는 과정**이 버그를 셋 뱉었다. 첫 표본을 뽑자마자 링크의 93.7%가
`node_modules/`·생성 캐시를 가리키고 있었다.

| # | 버그 | 원인 |
|---|---|---|
| 1 | 기본 ignore 패턴이 비어 있었다 | `06`/`16` 이 이름까지 지정한 패턴이 테스트 픽스처에만 존재. `IgnoreSection::default()` 는 `Vec::new()` |
| 2 | git 저장소가 아니면 `.gitignore` 전면 무시 | `ignore` 크레이트 `require_git` 기본값 `true`. vault 루트가 git 저장소가 아니면 하위 `.gitignore` 가 통째로 버려진다 |
| 3 | R2 가 링크 **대상**을 파일시스템에서 확인 | `Path::is_file` 을 쓰므로 인덱스에서 제외한 파일도 대상이 됐다. `neighbors` 가 준 uri 를 `read` 가 거부하는 모순 |
| 4 | Rust 파서가 인라인 `mod` 블록에 안 들어감 | `walk` 이 루트의 직계 자식만 훑었다. `#[cfg(test)] mod tests { .. }` 안의 함수가 전부 심볼 인덱스에서 누락 — 이 크레이트 자신의 테스트 139개도 검색되지 않았다. 런 2 의 Q9 가 이걸 잡았다 |

`16` 이 *"vendored 제외는 성능이 아니라 정밀도 문제이고 Phase 0 필수"* 라고 못박은
그 실패가 그대로 재현된 것이다. 수정 경과:

```text
최초        6,881 파일 / 2,654 링크 / 노이즈(from) 93.7%
1·2 수정    1,695 파일 /   168 링크 / 노이즈 from 0%, to 22건 잔존
3 수정      1,695 파일 /   146 링크 / 노이즈 from 0%, to 0%
```

**최초 링크의 94.5% 가 허구였다.** 이 상태로 측정했다면 수치 자체가 거짓이 된다.
